# Safety

- Loopback bind only (`PRIV_LOG_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1:7801` only (a test pins it) and mounts nothing from the host. Host header must be a loopback name (or one in `LAB_ALLOWED_HOSTS`); writes must be same-origin.
- **Mock sends nothing.** The netguard blocks every non-loopback socket, DNS lookup, fetch and UDP send, with a self-test (run by doctor and health) and a test that runs all 17 cases against an app configured for Real and asserts zero attempts and zero requests at the configured fake servers.
- **Real contacts only the two configured origins.** `realClient.js` is the only code that sends. It refuses any URL whose origin is not the gateway or the search endpoint before opening a socket; allows https (or http on loopback) only; refuses credentials in URLs; resolves host names itself and refuses private, link-local, metadata (169.254.x), CGNAT, multicast and reserved addresses (a mixed answer is refused), connecting to the address it checked; never follows a redirect (a 3xx is shown, its `Location` is never contacted); caps each request at 8 s and each response at 256 KB (reading stops at the cap); caps request bodies. The netguard allow-list is set to the two configured host names while Real is on and emptied when you switch back to Mock.
- **Confirm gate.** The first send in each browser tab needs the origins confirmed (`POST /api/confirm`, the gateway origin echoed back). Until then `POST /api/run` answers 412 and nothing is sent. Reset forgets the confirmation. Real is never on by default in Docker (`MODE=mock`).
- **The agent key is write-only.** It is read inside `config.js` from `~/Development/.env` / `STANDALONE_ENV` / the environment, handed to the Real client, and never returned by any API, never logged, and replaced by `***` in every raw request, response and error the client hands back. `GET /api/info` reports only that a key is configured. A test greps every API answer of a full Real run (including a gateway that echoes the Authorization header) for the key.
- **Pasted and returned log text is hostile data.** It is rendered as React text only (control and bidirectional characters shown as visible escapes), never as markup. The paste is capped at 200 KB and 500 lines of 4096 characters; the scorer reads it in one linear pass with `indexOf` and a key=value tokenizer, JSON is walked with an explicit stack (depth 5, 400 nodes), the few regexes run on values capped at 200 characters with no nested quantifiers. No `eval`, `Function` or `vm`.
- Writes are limited to `POST /api/mode|confirm|run|score|reset` with strict bodies (unknown keys refused, 300 KB limit). Nothing writes to a gateway's configuration: Real sends MCP calls and one read-only search.
- No identifiers from anywhere else: the capture is sanitised to placeholders and the validator rejects a non-reserved host or a real-looking UUID in it. Only `.example` / `.invalid` hosts ship. No tenant, credential or customer identifier ships.
